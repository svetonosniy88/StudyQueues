# Разработка StudyQueues

## Окружение

Основная платформа — Windows. Используйте Python 3.12 и виртуальное окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[test]'
.\.venv\Scripts\python.exe -m pytest -q
```

Интерфейс — PySide6 / Qt Widgets. Markdown-файлы являются источником задач; история и незавершённое занятие сохраняются в JSON. Отдельный сервер не требуется.

| Модуль | Назначение |
| --- | --- |
| `queue_store.py` | Чтение Markdown, точечные правки, резервные копии и конфликты. |
| `queue_window.py` | Ограниченные отрезки обзора. |
| `session.py` | Плановое и активное время, выполнение и восстановление. |
| `state_store.py` | Настройки, история и снимки занятия. |
| `ui.py`, `widgets.py`, `theme.qss` | Страницы, компоненты и оформление. |
| `native_window.py` | Оконное взаимодействие Windows. |

## Данные для разработки

Используйте `examples/` и `--demo`:

```powershell
.\.venv\Scripts\python.exe -m studyqueues --demo --data-dir .\local_data\development
```

Demo создаёт отдельную подпапку `demo` с копиями очередей. Обычные настройки не подключаются. Тесты используют временные профили; не подставляйте свои очереди в фикстуры и не публикуйте историю занятий.

## Изменения

- Сохраняйте небольшой Qt-проект и общий компонент строки задачи.
- Проверяйте переносы, выравнивание первой строки, состояния наведения и фокуса, узкое окно и системный масштаб.
- Отметка выполнения и её анимация должны следовать за успешной записью.
- Не сбрасывайте старые настройки и незавершённое занятие при обновлении.
- Меняйте только необходимые Markdown-строки и сохраняйте внешние правки при конфликте.
- Обновляйте руководство и CHANGELOG при изменении поведения.

## Проверки и снимки

Полный pytest проверяет Markdown, конфликты, учёт времени, восстановление и взаимодействие QtTest. Интерфейсные тесты используют offscreen backend. Пример проверки масштаба:

```powershell
$env:QT_SCALE_FACTOR = '1.5'
.\.venv\Scripts\python.exe -m pytest -q tests/test_ui.py
```

`scripts/product_screenshots.py` обновляет три демонстрационных снимка для README. Другие скрипты в `scripts/` проверяют геометрию и производительность; сгенерированные профили остаются в игнорируемой `local_data/`. Если системная временная папка недоступна, используйте уникальный `--basetemp local_data/pytest-<имя>` и `-p no:cacheprovider`.

GitHub Actions запускает проверки на Windows / Python 3.12. Используются официальные [actions/checkout](https://github.com/actions/checkout) и [actions/setup-python](https://github.com/actions/setup-python).

Для PR опишите конкретное изменение и проверку; для интерфейса приложите снимок на демонстрационных данных. Крупные изменения сначала обсудите в Issues.
