# Формат Markdown-очереди

[На главную](../README.md) · [Руководство](USER_GUIDE.md)

```markdown
# Университет

- [ ] Разобрать тему
    - [ ] Прочитать конспект
    - [x] Решить первый пример
- [x] Завершённая задача
```

- Корневая задача начинается с `- [ ] ` или `- [x] ` без отступа. `[X]` также читается как выполненное.
- Подпункт начинается с **четырёх обычных пробелов**, затем такого же маркера. Поддерживается один уровень вложенности.
- Каждый пункт занимает одну непустую физическую строку. Длинный текст приложение переносит на экране автоматически.
- Подпункты идут непосредственно после своего родителя. Нумерованные списки, табы, два пробела и дополнительные уровни не поддерживаются.
- Пустой список допустим. Завершённый родитель не должен содержать невыполненных подпунктов.

При сохранении приложение назначает скрытый ID:

```markdown
- [ ] Разобрать тему <!-- task:a1b2c3d4 -->
```

Новые пункты можно писать без ID. Существующие комментарии сохраняйте; при копировании задачи удалите её ID, чтобы приложение создало новый. Одинаковый текст задач допустим, одинаковые ID — нет. В ID используются латинские буквы, цифры, дефис и подчёркивание.

Заголовки, вводный текст, YAML, блоки кода, BOM и переводы строк сохраняются. Чекбоксы в YAML и кодовых блоках не считаются задачами. Приложение меняет нужные строки, а не переформатирует заметку целиком.

## Порядок

Порядок задач соответствует файлу. Добавление родителя из обзора вставляет его перед первым корневым блоком, сохраняя вводный текст документа. Из занятия новая задача вставляется сразу после текущего блока с подпунктами. Новый подпункт добавляется в конец выбранного родителя.

Перетаскивание перемещает задачу вместе с подпунктами и действует в текущем отрезке обзора. Вставка после последней показанной задачи означает позицию перед следующим блоком файла, если он существует.

## Внешнее редактирование

Очередь можно открывать в Obsidian, другом редакторе или изменять скриптом. Перед работой прочитайте актуальный файл; сохраняйте чужие задачи, отметки и ID. После изменения нажмите `↻` в приложении.

Перед записью StudyQueues сравнивает текущее содержимое с прочитанным, делает резервную копию и атомарно заменяет файл. При конфликте чужая версия сохраняется. Эта проверка не заменяет межпроцессную транзакцию: выполняйте правки последовательно.
